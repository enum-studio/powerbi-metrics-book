# powerbimetricsbook.io: the project's website

Date: 2026-10-27. Mode: spec together, then attended. Built inline in one session.

## What it is

powerbimetricsbook.io is the public home of Power BI Metrics Book. A landing page sits at `/`, and the documentation is at `/docs/`. Every page links to the GitHub repository, github.com/enum-studio/powerbi-metrics-book.

It is a site for an open-source project, and nothing else. The project has no paid tier, no hosted version, and none is planned (Martin, 2026-10-27). So the site has no pricing, sign-up, demo booking, customer logos, testimonials or star count. Its calls to action are: read the docs, see the code on GitHub, and, from 0.1, install it. The one exception, at the bottom of the page, points a company that wants help with implementation or strategy to Enum Studio (Martin, 2026-10-27).

## Who reads it

- A company built on Power BI that wants its agents to use that Power BI, without switching away from it.
- The person who sets it up: a Power BI admin, or an engineer next to one.

The message sheet, with Martin's own positioning, is kept beside this spec in the notes of the session that built it. The parts the page uses are in the sections below.

## Structure

One repository builds one static folder:

| Path | Comes from | What |
| --- | --- | --- |
| `/` | `apps/site` (Astro, no Starlight) | The landing page |
| `/docs/` | `apps/docs` (Starlight), built with `PBMB_DOCS_SITE=1` | The docs, as the product serves them, plus the public extras below |

`pnpm --filter @powerbi-metrics-book/site build` builds the docs for the site, builds the landing page, and copies the docs build to `apps/site/dist/docs/`. That folder is the whole site.

**Why the landing page is not a Starlight page.** Starlight's `base` is `/docs`, because the api serves the same build at `/docs` inside every deployment. A Starlight page cannot sit at `/` without moving every docs URL and breaking the copy in the product.

**What the public docs build adds** (only with `PBMB_DOCS_SITE=1`):
- `site: https://powerbimetricsbook.io`, for canonical links and the sitemap;
- the site title links to `/`, the landing page, instead of `/docs/`.

Both builds get a GitHub link in the docs header.

The project is released. Remove the prerelease notices from the landing page, docs and README, and describe the release in the changelog (Martin, 2026-11-26).

**Versions.** There is no version switcher. Every deployment serves the docs of its own version at its own `/docs`, so the public site carries the latest release only.

**Changelog.** It lives in `CHANGELOG.md` in the repository. `scripts/sync-repo-docs.mjs` copies it to the Reference part as `/docs/reference/changelog/`, the same way it copies `SECURITY.md`. The header's Changelog link goes there.

## The landing page, top to bottom

The copy is short: each line names one thing the drawing beside it shows (Martin, 2026-10-27, after anfra.ai).

1. **Header.** The Enum Studio mark and the name, then Demo, Docs, Changelog, a GitHub icon and a switch between light and dark mode; Changelog is hidden below 560px. Until the reader picks a mode, the system setting decides. The choice is kept under Starlight's `starlight-theme` key, so the docs open in it too (Martin, 2026-10-27). The docs header starts with the same mark and name, which lead back to `/`, and has the same GitHub icon beside search and the theme switch.
2. **Hero.** "Agent First BI for Power BI." and one line under it. The buttons are "Get started" (to the get-started section), "See the code on GitHub" and "Try the demo" (to demo.powerbimetricsbook.io, added 2026-11-12 with Martin's word, `docs/specs/2026-11-12-public-demo.md`). Beside them is the isometric stack: Power BI at the bottom with three datasets, the book in the middle with the `net_sales` metric and a CSV file, the agents and internal tools on top. Power BI's tiles carry small bar charts and the book carries the metric chip and a CSV sheet. The top layer is a solid plane: Claude Code, Codex and Cursor lie on it as tiles, and two windows stand at its back, Claude Code's run and an internal tool: a reorder list with the five products lowest on stock in the sample's Retail dataset, each with an order button. A callout names each layer. The top layer's callout is a card with an example run: four steps (`search`, `get_metric`, `execute_dax`, then `curl -o` on the answer's `csv_url`), each lighting up the shapes it touches. The layers build in on load and pulses run along the wires. `src/drawing/hero.ts` draws it.
3. **Where it sits.** "Power BI has the numbers you trust. Your agents can't use them yet." Three points (reports, an agent on raw DAX, Microsoft's connectors), one closing line, and a two-axis chart on a fine grid, same numbers as your reports against open to any agent, with the book alone in the corner that is both. The corner and its dot reveal themselves when the chart scrolls into view.
4. **Right every time, so your agent can do the work that matters.** The same heading as Metrics Book's section, adapted to Power BI. The opening says why an agent must be right every time, quotes Microsoft's Copilot guide on ambiguous data, and says a Power BI semantic model already holds the measures, often one number in several datasets under several names, which the book turns into one definition per metric for any agent. Four parts between hairlines: every time, not most of the time (dbt Labs' benchmark); one definition, not forty lookalikes (Anthropic's report, and that a person approves each metric here); answers without the wait (Sigma's survey); and hand over the work with real upside (jobs a Power BI company can hand over). Beside them, one mark per answer of dbt Labs' benchmark, sticky on a wide screen: Metrics Book's `AnswerGrid`, ported as it is, with text-to-SQL's wrong answers scattered among its right ones (Martin, 2026-10-29). Each outside number carries a numbered citation into the Sources section. The cost argument of Metrics Book's page is left out: it compares against cloud warehouses, and a Power BI customer has already paid for Power BI (Martin, 2026-10-29).
5. **Three things break when an agent writes its own DAX.** Three rows: the wrong measure, a full context, running as someone else. Each says what happens here instead, beside a small picture.
6. **Get started.** "From an empty VM to your first agent query in under 30 minutes", and under it "Three commands start the stack. Then a setup in your browser checks each step before the next." A track of six steps over the step's command: install, write, start, open the setup link, the ten checked steps, ask your agent. The track is tabs; it never moves by itself. A link to the quickstart sits under it.
7. **Add one address to your agent.** Three numbered steps, with tabs for the Claude Code, Codex and Cursor setup taken from `set-up/agents.md`. Below are one line each for the command line and the REST API.
8. **Build internal tools on the same numbers.** The agent finds the data over MCP; a company's own tool then runs the same DAX through the REST API with a service account's API key, without writing Power BI sign-in code. The commands sit beside a small sales dashboard such a tool would be, with the sample tenant's real 2025 net sales by month; its bars grow in on scroll and show each month's value on hover. A four-row table below compares the agent and the tool, and the small print gives the limits of service-account queries.
9. **Everything runs on one VM.** The VM guide's minimum size, a link to the Deploy guides, and one question's path through the stack, drawn the way Metrics Book draws its own: the VM as a slab with the proxy, the api, the worker, Postgres and Cerbos on it, and Power BI, the embedding provider and the agent outside. Five steps (sync, ask, check, query, keep) light the parts and traces they use and play by themselves, each with a timer line; a click picks one and stops the playing. On a phone the drawing shows only the VM, so the containers' names stay readable.
10. **Where to run it.** The four deploy guides plus Kubernetes, each saying whether the guide has been followed on a real account (from the README).
11. **Open source.** The Apache 2.0 licence, how to contribute, how to report a security issue, and the sister product Metrics Book.
12. **Sources.** The heading on the left and a numbered list on the right, in the form and styles Metrics Book's page uses: who, the title linked, the date, a note on the method and on the source's stake (Microsoft sells Copilot, dbt Labs makes a semantic layer, Anthropic makes Claude, Sigma sells BI software), and links back to each citation.
13. **Need help with implementation or strategy?** One line on Enum Studio and a button to enumstudio.com.
14. **Footer.** Docs, GitHub, Changelog, Licence, Security, and "Built and maintained by Enum Studio".

## Settled by inspection (do not re-derive)

Martin picked these from rendered prototypes on 2026-10-27:

- The headline is "Agent First BI for Power BI." The Orders headline was tried and dropped.
- The line under it is "Your agents ask. Your Power BI answers, with one definition per metric."
- The hero is the text on the left and the isometric stack on the right, in the accent green. It replaced the agent transcript and the install commands, which were in the hero first.
- The query's result is a CSV file on the book's layer, next to `net_sales`, not on the agents' layer, where it read as unclear.
- The second section places the product with the two-axis chart, before any feature. The product's name sits inside its green panel, not across its edge (Martin, 2026-10-27).
- "Three things break" is three rows, each with what happens here instead. The context row says plainly that the agent downloads the full result as a CSV file into its folder, and only a preview goes into the context.
- Get started is a six-step track over one command at a time. Its steps show the real measured times only. Its heading claims under 30 minutes in all, Martin's estimate until a full setup on a real tenant has been timed (Martin, 2026-10-28). Replace it with the measured time then.
- The sample tenant's names are plain ("Sales"), on the landing page and in the docs, and a command meant to be run as written on the sample tenant, such as one under "## Check", uses the same name (Martin, 2026-10-27; the prefix "Sample data: " went in `docs/specs/2026-10-27-sample-tenant.md`).
- The agents section is numbered steps on the left and tabs per client on the right.
- The stack section draws one question's path through the VM the way Metrics Book's "Everything runs on one server" does, with steps beside it, and links to the Deploy guides (Martin, 2026-10-27). The landing page names no VM provider. The Deploy overview and the VM guide recommend Hetzner and Netcup, because their VMs cost much less than Azure, GCP or AWS (Martin, 2026-10-27).
- The hero is drawn in the manner of anfra.ai's: a faded isometric grid behind it, hatched sides, thin strokes, glowing nodes, real miniature content on each layer, a build-in on load and the example run card that steps through the run. Motion is fine where it shows how the product works, and it stops under reduced motion (Martin, 2026-10-27).
- The hero's top layer shows both what connects and what you build: the agents as tiles and an internal tool beside the agent's window, the way Metrics Book's "Data apps and agents" layer does (Martin, 2026-10-28).
- The hero's internal tool is an app, a reorder list with order buttons, the way Metrics Book's hero shows its reorder tool, not the sales dashboard (Martin, 2026-10-29). The internal tools section keeps its sales dashboard.
- The case for a semantic layer is made with checked outside evidence, in the shape of Metrics Book's "Right every time" section (Martin, 2026-10-29). Two of Metrics Book's figures did not hold at their sources and are left out: Sigma's release does not say data experts spend 20 to 49% of their time on ad hoc reports, and Anthropic's under 21% is accuracy without its skills, not without its semantic layer.
- The look is the existing tokens: paper, one bottle-green accent, 2px radius, Inter and Plex Mono, and the Enum Studio mark beside the name. There are no section eyebrows, no icons in tinted squares and no card grids.

## Hosting

The site runs on Dokploy, on the same server as Enum Studio's other sites, not on Cloudflare Workers as first planned (Martin, 2026-10-27). `apps/site/Dockerfile` builds the landing page and the docs into one image, where Caddy serves the files on port 8080. `apps/site/Caddyfile` keeps what the Workers config did: the trailing-slash redirect, and the nearest 404 page under `/docs` and outside it. `www` redirects to the bare domain.

Dokploy builds from `main` when a push changes a path the build reads. The DNS is two `A` records in Cloudflare, not proxied, the same as the other sites, and Traefik in Dokploy gets the certificates. The settings are in `apps/site/README.md`.

**Blocker before launch.** The repository is private, so every GitHub link returns a 404 for a visitor until it goes public.
